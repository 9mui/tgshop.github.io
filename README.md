## 1. Что умеет приложение

Приложение содержит:

- каталог товаров в адаптивной сетке;
- автоматические категории;
- добавление товаров в корзину;
- увеличение и уменьшение количества;
- подсчёт количества товаров и итоговой суммы;
- отдельный экран корзины;
- удаление товара из корзины;
- сохранение корзины после перезагрузки страницы;
- поддержку светлой и тёмной темы Telegram;
- нативные Telegram-кнопки `MainButton` и `BackButton`;
- тактильный отклик через `HapticFeedback`;
- поддержку safe area на мобильных устройствах;
- резервные кнопки для работы в обычном браузере;
- отправку состава заказа Telegram-боту через `sendData()`.

### Пользовательский сценарий

1. Пользователь открывает Mini App.
2. Выбирает категорию.
3. Добавляет товары.
4. Меняет количество кнопками «−» и «+».
5. Открывает корзину.
6. Проверяет состав и сумму.
7. Нажимает «Оформить заказ».
8. Приложение отправляет боту идентификаторы товаров и количество.

## 2. Как устроен проект

```text
tgshop.github.io/
├── index.html
├── styles.css
├── app.js
├── products.js
├── README.md
└── images/
    ├── tshirt.webp
    ├── jeans.webp
    └── hoodie.webp
```

| Файл | Назначение | Когда редактировать |
|---|---|---|
| `products.js` | Товары, цены, категории и пути к фотографиям | При изменении ассортимента |
| `images/` | Локальные фотографии товаров | При добавлении или замене фото |
| `index.html` | Основная разметка, заголовок страницы и подключение файлов | При изменении названия или структуры |
| `app.js` | Каталог, корзина, подсчёт суммы и Telegram API | При изменении логики |
| `styles.css` | Цвета, размеры, сетка и внешний вид | При изменении дизайна |
| `README.md` | Инструкция по проекту | При изменении возможностей |

Для обычного управления магазином чаще всего нужны только `products.js` и папка `images/`.

## 3. Быстрое редактирование через GitHub

### Редактирование файла

1. Откройте репозиторий.
2. Выберите нужный файл, например `products.js`.
3. Нажмите значок карандаша **Edit this file**.
4. Внесите изменения.
5. Нажмите **Commit changes**.
6. Введите понятное описание, например `Добавлен новый товар`.
7. Сохраните изменение в ветку `main`.

После коммита GitHub Pages обычно обновляется в течение нескольких минут.

### Загрузка фотографии

1. Откройте папку `images/`.
2. Нажмите **Add file** → **Upload files**.
3. Выберите изображение.
4. Нажмите **Commit changes**.
5. Укажите имя файла в `products.js`.

GitHub чувствителен к регистру. `Jacket.webp` и `jacket.webp` считаются разными файлами.

## 4. Управление товарами

Все товары находятся в массиве `PRODUCTS` внутри `products.js`.

Пример товара:

```js
{
  id: 1,
  title: "Базовая футболка",
  price: 1490,
  category: "Футболки",
  image: "images/tshirt.webp",
},
```

### Поля товара

| Поле | Тип | Пример | Описание |
|---|---|---|---|
| `id` | Число | `4` | Уникальный идентификатор |
| `title` | Строка | `"Куртка"` | Название в каталоге и корзине |
| `price` | Число | `7990` | Цена без пробелов и символа валюты |
| `category` | Строка | `"Куртки"` | Категория товара |
| `image` | Строка | `"images/jacket.webp"` | Путь к фотографии |

### Добавление товара

Добавьте новый объект перед закрывающей скобкой `];`:

```js
const PRODUCTS = [
  {
    id: 1,
    title: "Базовая футболка",
    price: 1490,
    category: "Футболки",
    image: "images/tshirt.webp",
  },
  {
    id: 4,
    title: "Куртка демисезонная",
    price: 7990,
    category: "Куртки",
    image: "images/jacket.webp",
  },
];
```

Каждый товар отделяется запятой.

### Изменение товара

Для изменения названия:

```js
title: "Футболка оверсайз",
```

Для изменения цены:

```js
price: 1790,
```

Для переноса в другую категорию:

```js
category: "Базовая одежда",
```

Для замены фотографии:

```js
image: "images/tshirt-black.webp",
```

### Удаление товара

Удалите весь объект товара, включая фигурные скобки и соседнюю запятую.

Удаление товара не удаляет его фотографию автоматически. Неиспользуемое изображение можно отдельно удалить из `images/`.

### Изменение порядка

Порядок объектов в `PRODUCTS` определяет порядок карточек в каталоге. Переместите весь объект выше или ниже.

### Правила для `id`

- Каждый `id` должен быть уникальным.
- Используйте целые положительные числа.
- Не меняйте `id` существующего товара без необходимости.
- После удаления товара старый `id` лучше не использовать повторно.
- Одинаковые `id` приведут к неправильной работе корзины.

## 5. Управление категориями

Категории создаются автоматически:

```js
const CATEGORIES = ["Все", ...new Set(PRODUCTS.map((product) => product.category))];
```

Отдельный список категорий редактировать не нужно.

### Добавление категории

Укажите новое значение `category` хотя бы у одного товара:

```js
category: "Аксессуары",
```

После публикации кнопка «Аксессуары» появится автоматически.

### Переименование категории

Замените старое название у всех товаров этой категории:

```js
category: "Верхняя одежда",
```

Если изменить только один товар, появятся две категории.

### Удаление категории

Удалите все товары этой категории или назначьте им другую категорию. Пустые категории не отображаются.

### Важные правила

- `"Худи"` и `"худи"` считаются разными категориями.
- Лишний пробел также создаёт новую категорию: `"Худи"` и `"Худи "`.
- Используйте одинаковое написание во всех товарах.
- Категории выводятся в порядке первого появления в `PRODUCTS`.
- Категория «Все» добавляется приложением автоматически.

## 6. Изменение цен и валюты

### Изменение цены

В `products.js` цена указывается числом:

```js
price: 4590,
```

Правильно:

```js
price: 7990,
```

Неправильно:

```js
price: "7 990 ₽",
price: "7990",
price: 7 990,
```

Приложение само форматирует `7990` как `7 990 ₽`.

### Изменение валюты

Форматирование находится в `app.js`:

```js
function formatPrice(value) {
  return `${new Intl.NumberFormat("ru-RU").format(value)} ₽`;
}
```

Для узбекских сумов можно заменить функцию:

```js
function formatPrice(value) {
  return `${new Intl.NumberFormat("uz-UZ").format(value)} so'm`;
}
```

Для символа доллара:

```js
function formatPrice(value) {
  return `$${new Intl.NumberFormat("en-US").format(value)}`;
}
```

После изменения `app.js` увеличьте версию подключения в `index.html`, например:

```html
<script src="app.js?v=3"></script>
```

Это помогает Telegram и браузеру не использовать старую версию из кеша.

### Цены с копейками

Текущая структура рассчитана на целые числа. Для дробных цен потребуется заранее определить способ хранения и округления. Для платёжных систем безопаснее хранить деньги в минимальных единицах валюты, например в копейках или центах.

## 7. Работа с фотографиями

### Рекомендуемые параметры

| Параметр | Рекомендация |
|---|---|
| Формат | WebP |
| Соотношение сторон | 3:4 |
| Размер | 720×960 или 600×800 |
| Вес | Желательно до 200 КБ |
| Цветовой профиль | sRGB |
| Имя файла | Латиница, нижний регистр, без пробелов |

Хорошие имена:

```text
black-jacket.webp
blue-jeans.webp
white-tshirt.webp
```

Плохие имена:

```text
Моя куртка.webp
Фото 1.jpg
IMAGE FINAL (2).png
```

### Подключение фотографии

Если файл находится в `images/jacket.webp`, товар должен содержать:

```js
image: "images/jacket.webp",
```

Путь указывается относительно `index.html`.

### Замена существующего фото

Есть два варианта:

1. Загрузить новый файл с тем же именем.
2. Загрузить файл с новым именем и изменить `image` в `products.js`.

Второй вариант надёжнее, потому что старое изображение может остаться в кеше.

Пример:

```js
image: "images/jacket-v2.webp",
```

### Внешние ссылки

Внешние URL технически возможны:

```js
image: "https://example.com/jacket.webp",
```

Но локальные файлы надёжнее. Внешний сайт может запретить загрузку, изменить адрес или удалить изображение. Не используйте ссылки на страницы Pinterest, Instagram или интернет-магазинов вместо прямых ссылок на файл.

### Если фото не отображается

Проверьте:

- файл действительно загружен в `images/`;
- имя и расширение полностью совпадают;
- регистр букв совпадает;
- в имени нет лишних пробелов;
- путь начинается с `images/`;
- файл открывается напрямую через GitHub Pages;
- формат поддерживается браузером.

## 8. Изменение названия и текстов

### Название вкладки браузера

В `index.html`:

```html
<title>Магазин одежды</title>
```

### Заголовок каталога

Начальное значение находится в `index.html`:

```html
<h1 id="screenTitle" class="app-title">Магазин одежды</h1>
```

После возврата из корзины заголовок задаётся в `app.js`:

```js
elements.title.textContent = "Магазин одежды";
```

Меняйте оба значения одинаково.

### Подзаголовок

Начальное значение в `index.html`:

```html
<p id="screenSubtitle" class="app-subtitle">Базовые вещи на каждый день</p>
```

Значение после возврата в каталог в `app.js`:

```js
elements.subtitle.textContent = "Базовые вещи на каждый день";
```

### Тексты корзины

В `app.js` можно изменить:

- `"Корзина"`;
- `"Проверьте состав заказа"`;
- `"Оформить заказ"`;
- `"Корзина пуста"`;
- `"Добавьте вещи из каталога"`.

После изменения JavaScript обновите параметр `?v=` в `index.html`.

## 9. Корзина и оформление заказа

Корзина хранит только:

```js
{ id: 1, qty: 2 }
```

Название, фотография и цена берутся из `PRODUCTS`.

### Хранение корзины

Данные сохраняются в `localStorage` под ключом:

```js
const storageKey = "tgshop-cart-v2";
```

Поэтому корзина сохраняется после перезагрузки на том же устройстве и в том же браузере.

Если структура корзины существенно изменится, увеличьте версию ключа:

```js
const storageKey = "tgshop-cart-v3";
```

У пользователей при этом будет создана новая пустая корзина.

### Очистка корзины при тестировании

В инструментах разработчика выполните:

```js
localStorage.removeItem("tgshop-cart-v2");
location.reload();
```

### Формат заказа

При оформлении отправляется:

```json
{
  "version": 2,
  "items": [
    { "id": 1, "qty": 2 },
    { "id": 3, "qty": 1 }
  ]
}
```

Цена и итог намеренно не отправляются как доверенные значения.

## 10. Интеграция с Telegram

SDK подключается в `index.html`:

```html
<script src="https://telegram.org/js/telegram-web-app.js"></script>
```

При запуске внутри Telegram приложение:

- вызывает `ready()`;
- раскрывает Mini App через `expand()`;
- применяет цвета темы Telegram;
- использует нативную нижнюю кнопку;
- показывает нативную кнопку «Назад» в корзине;
- включает тактильный отклик;
- предупреждает о закрытии при непустой корзине.

### Работа в обычном браузере

В обычном браузере `initData` отсутствует. Поэтому приложение:

- показывает собственную нижнюю кнопку;
- показывает собственную кнопку возврата;
- не пытается вызвать Telegram-only функции;
- вместо реальной отправки заказа показывает уведомление.

Это позволяет проверять интерфейс через GitHub Pages, но не заменяет тестирование внутри Telegram.

### Подключение через BotFather

Общий порядок:

1. Создайте или выберите бота в `@BotFather`.
2. Настройте Mini App для этого бота.
3. Укажите HTTPS-адрес GitHub Pages:
   `https://9mui.github.io/tgshop.github.io/`
4. Добавьте кнопку запуска Mini App.
5. Откройте приложение из Telegram и проверьте заказ.

Интерфейс BotFather может меняться. Используйте актуальные подсказки самого бота и официальную документацию Telegram Mini Apps.

## 11. Безопасность и серверная обработка

GitHub Pages содержит только клиентскую часть. Пользователь может просматривать и изменять JavaScript в своём браузере.

Поэтому нельзя доверять данным, пришедшим от клиента.

### Обязательные правила для бота или backend

1. Принимать только `id` и `qty`.
2. Находить товар по `id` в доверенной базе или серверном каталоге.
3. Повторно получать актуальную цену.
4. Проверять наличие товара.
5. Проверять допустимое количество.
6. Самостоятельно рассчитывать итоговую сумму.
7. Валидировать `Telegram.WebApp.initData` на сервере.
8. Проверять срок `auth_date`.
9. Не хранить токен бота в HTML или JavaScript.
10. Не принимать клиентский `total` как окончательную сумму.

### Важное ограничение текущего проекта

Сейчас ассортимент находится в публичном `products.js`. Это удобно для небольшого демо-магазина, но не является серверной базой данных.

Для реального магазина с оплатой рекомендуется:

- хранить товары и цены на backend;
- загружать каталог через API;
- создавать заказ на сервере;
- возвращать серверный номер заказа;
- подключать оплату только после серверной проверки.

### Секреты

Никогда не добавляйте в GitHub:

- токен Telegram-бота;
- API-ключи;
- пароли;
- секрет платёжной системы;
- приватные данные покупателей.

Публичный репозиторий и GitHub Pages доступны всем.

## 12. Локальный запуск

Не рекомендуется открывать `index.html` двойным кликом. Используйте локальный HTTP-сервер.

### Python

```bash
python -m http.server 4173
```

После запуска откройте:

```text
http://127.0.0.1:4173/
```

### Что проверить локально

- товары появились;
- фотографии загрузились;
- категории переключаются;
- кнопки количества работают;
- сумма меняется правильно;
- корзина открывается;
- удаление работает;
- возврат в каталог работает;
- после перезагрузки корзина сохраняется;
- в консоли браузера нет ошибок.

Нативные Telegram-кнопки локально не появятся без запуска внутри Telegram.

## 13. Публикация через GitHub Pages

GitHub Pages публикует файлы из ветки `main`.

### Обычное обновление каталога

1. Измените `products.js`.
2. При необходимости загрузите изображения.
3. Сделайте commit в `main`.
4. Подождите несколько минут.
5. Откройте публичный URL и обновите страницу.

### Обновление JavaScript или CSS

В `index.html` используются версии ресурсов:

```html
<link rel="stylesheet" href="styles.css?v=2" />
<script src="products.js?v=2"></script>
<script src="app.js?v=2"></script>
```

После существенного изменения этих файлов увеличьте число:

```html
<link rel="stylesheet" href="styles.css?v=3" />
<script src="products.js?v=3"></script>
<script src="app.js?v=3"></script>
```

Это предотвращает загрузку старых файлов из кеша GitHub Pages, браузера или Telegram WebView.

### Проверка публикации

Проверьте:

- страницу репозитория;
- последний commit в `main`;
- раздел **Actions**, если Pages ещё не обновился;
- публичный URL в обычном браузере;
- Mini App внутри Telegram.

## 14. Типичные проблемы

### Товар не появился

- Проверьте синтаксис `products.js`.
- Проверьте запятые и фигурные скобки.
- Убедитесь, что изменение сохранено в `main`.
- Подождите обновления Pages.
- Обновите версию `products.js?v=` в `index.html`.

### Появились две похожие категории

Причина обычно в регистре или пробеле:

```js
category: "Худи",
```
